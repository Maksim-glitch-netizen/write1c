# Развёртывание проекта 1С:Управление холдингом

Этот комплект нужен для подготовки нового проекта разработки. Настройку выполняет
агент по текстовой инструкции: выбирает папку, проводит опрос и адаптирует рабочие правила.

## 1. Скачать и распаковать

Скачайте проект целиком и распакуйте архив в любую удобную папку.
Сохраните весь комплект, включая скрытые файлы. В распакованной папке должны находиться
`README.md`, `AGENTS.md`, `.gitignore` и `1c_core`.
Если архив содержит ещё одну вложенную папку, выбирайте именно папку с этими файлами.
Пустые рабочие и служебные папки могут отсутствовать в архиве: агент создаст их
в целевом проекте, включая обязательную `1c_works_files`.

## 2. Запустить установку в агенте

Выберите распакованную папку как проект в агенте, откройте чат и напишите:

```text
установить
```

Агент прочитает правила и предложит, в какую папку развернуть новый проект.
**Рекомендуется отдельная новая пустая папка.** Можно выбрать предложенный новый путь
или указать свой. Если путь ещё не сообщён, агент запросит его отдельным вопросом.

Распакованная папка служит источником шаблона. Рабочий проект создаётся в выбранной
целевой папке; ответы, подключения и результаты настройки сохраняются там.
Для следующего независимого проекта этот же незаполненный шаблон можно использовать снова.

## 3. Ответить на вопросы настройки

Агент задаёт строго один вопрос за раз и предлагает варианты, где это возможно.
Он выяснит подключение к базе разработки, skills и MCP, наличие хранилищ,
список расширений и приоритеты разработки. Расширения можно определить автоматически,
если доступно разрешённое чтение текущей базы, либо указать вручную.

По умолчанию база использует логин и пароль. Для передачи пароля предлагаются
локальный файл, переменная окружения или доступное хранилище секретов.
После выбора отдельным вопросом уточняется путь, имя переменной или ссылка на запись.
В настройках сохраняется ссылка на пароль.

Дождитесь сообщения агента о завершении настройки и её проверках. Если какой-то
обязательный этап заблокирован, агент сообщит причину и следующий шаг.
Перед итоговым сообщением агент очищает установочные материалы в целевом проекте.
В `1c_core/docs/развертывание/` остаются `ПРОФИЛЬ.json` и `СОСТОЯНИЕ.json`;
выгруженные исходники сохраняются в `1c_works_files`, неизвестные пользовательские
файлы сохраняются с объяснением. Незаполненный распакованный шаблон остаётся целым.
Состояние различает завершение развёртывания, очистку и техническую готовность:
блокер отдельного инструмента не запускает повторную установку рабочего проекта.

## 4. Открыть развёрнутый проект для работы

После завершения создайте **новый проект в агенте**:

1. Выберите целевую папку, в которую агент развернул проект + "/1c_core", как основную папку проекта.
2. В первом рабочем чате отправьте:

```text
Прочитай 1c_core/AGENTS.md, профиль и состояние в 1c_core/docs/развертывание.
Работай по правилам этого проекта.
```

Теперь задачи разработки ставьте в этом новом проекте агента.

## Что будет в целевой папке

```text
<целевая папка>/
  README.md
  .gitignore
  1c_core/
    AGENTS.md
    skills/
    docs/
      развертывание/
        ПРОФИЛЬ.json
        СОСТОЯНИЕ.json
      verified-1c-commands/
  1c_works_files/
    components/
    tasks/
```

Рабочие правила находятся в [1c_core/AGENTS.md](1c_core/AGENTS.md).
Корневой `AGENTS.md` нужен для запуска установки из шаблона и **в новый проект не копируется**.
Служебные навыки `1c-core-skills` и `1c-project-setup` также не копируются в новый проект.
При этом весь обязательный набор рабочих навыков в `1c_core/skills` и папка docs сохраняются.
`verified-1c-commands` остаётся пустой до появления проверенных команд в ходе разработки.

Подробный порядок установки находится в распакованном шаблоне:
`1c_core/docs/развертывание/ИНСТРУКЦИЯ.md`.
В готовом проекте этот установочный документ удалён; рабочие правила и порядок
возобновления прерванной очистки находятся в `1c_core/AGENTS.md`.
