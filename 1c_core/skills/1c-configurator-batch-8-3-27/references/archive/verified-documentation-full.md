# Пакетный режим Конфигуратора 1С:Предприятие 8.3.27

## Инструкция для IT-специалиста и разработчика 1С

**Версия документа:** 1.0  
**Дата проверки:** 6 августа 2026 года  
**Целевая платформа:** 1С:Предприятие 8.3.27  
**Режим:** `1cv8.exe DESIGNER`  
**Операционная система в примерах:** Windows  
**Политика источников:** только официальная документация фирмы «1С» и официальный портал 1Ci Knowledge Base.

---

## 0. Назначение и границы документа

Документ описывает пакетную работу Конфигуратора с:

- основной конфигурацией;
- расширениями конфигурации;
- XML-выгрузкой и XML-загрузкой;
- хранилищем конфигурации и отдельными хранилищами расширений;
- обновлением конфигурации базы данных;
- захватом, отменой захвата и помещением объектов в хранилище;
- диагностикой результата пакетного запуска.

Документ **не смешивает** следующие механизмы:

1. `DumpConfigToFiles` / `LoadConfigFromFiles` - полная или частичная работа с XML-представлением метаданных.
2. `DumpConfigFiles` / `LoadConfigFiles` - выгрузка и загрузка отдельных свойств объектов: модулей, макетов, справочной информации, картинок и прав.
3. `DumpCfg` / `LoadCfg` - работа с бинарными файлами `.cf` и `.cfe`.
4. Команды `ConfigurationRepository...` - работа с хранилищем конфигурации, а не с каталогом XML-файлов.
5. `UpdateDBCfg` - применение изменённой конфигурации к конфигурации базы данных.

> Важно: хранилище конфигурации хранит объекты конфигурации. Произвольные XML-файлы нельзя «положить в хранилище» напрямую. Сначала XML загружается в редактируемую конфигурацию, после чего изменённые объекты помещаются в хранилище командой `ConfigurationRepositoryCommit`.

# 1. Базовая командная строка

## 1.1. Общий шаблон

```text
"<путь к 1cv8.exe>" DESIGNER <подключение к ИБ> <аутентификация ИБ> <пакетная команда> <служебные параметры>
```

Пример для рабочей клиент-серверной базы:

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /DisableStartupMessages ^
  /Out "<PROJECT_ROOT>\logs\designer.log" ^
  /DumpResult "<PROJECT_ROOT>\logs\designer.result" ^
  /DumpConfigToFiles "<PROJECT_ROOT>\xml\main" ^
  -Format Hierarchical
```

В `cmd.exe` для переноса команды на следующую строку используется `^`. В реальном `.bat`-файле после `^` не должно быть пробелов.

## 1.2. Запуск из PowerShell

В PowerShell путь к исполняемому файлу вызывается оператором `&`. Одинарные кавычки вокруг всей команды использовать нельзя как в `cmd.exe`: такая строка будет воспринята как текст.

```powershell
$OneC = '<PLATFORM_EXECUTABLE>'

& $OneC DESIGNER `
    /S '<SERVER>\<INFOBASE>' `
    /WA+ `
    /DisableStartupDialogs `
    /DisableStartupMessages `
    /Out '<PROJECT_ROOT>\logs\designer.log' `
    /DumpResult '<PROJECT_ROOT>\logs\designer.result' `
    /DumpConfigToFiles '<PROJECT_ROOT>\xml\main' `
    -Format Hierarchical

$ProcessExitCode = $LASTEXITCODE
```

## 1.3. Основные параметры подключения

### `/F <каталог>`

Подключение к файловой информационной базе. Каталог должен содержать файл `1Cv8.1CD`.

```bat
/F "<INFOBASE_DIRECTORY>"
```

### `/S <адрес>`

Подключение к клиент-серверной информационной базе.

Формат:

```text
сервер/имя_ИБ
```

В Windows также часто используется обратная косая черта:

```bat
/S "<SERVER>\<INFOBASE>"
```

### `/IBName <имя в списке баз>`

Выбор базы по имени из списка информационных баз. Для автоматизации надёжнее использовать `/F` или `/S`, потому что одинаковые имена в списке баз приводят к ошибке выбора.

### `/N<имя>`

Имя пользователя информационной базы.

```bat
/N"<INFOBASE_USER>"
```

### `/P<пароль>`

Пароль пользователя информационной базы. Если пароль пустой, официальная документация предписывает **не указывать параметр `/P`**.

```bat
/P"<PASSWORD_FROM_SOURCE>"
```

### `/WA+`

Требовать аутентификацию операционной системы.

### `/WA-`

Запретить аутентификацию операционной системы и использовать пользователя информационной базы, заданного через `/N` и `/P`.

> Если `/WA` не указан, платформа трактует это как `/WA+`.

## 1.4. Служебные параметры пакетного запуска

### `/Out <файл> [-NoTruncate]`

Записывает служебные сообщения Конфигуратора в файл UTF-8.

```bat
/Out "<LOG_DIRECTORY>\designer.log"
```

С `-NoTruncate` существующий файл не очищается:

```bat
/Out "<LOG_DIRECTORY>\designer.log" -NoTruncate
```

Для автоматизации обычно лучше создавать отдельный лог на каждый запуск, а не смешивать несколько операций в одном файле.

### `/DumpResult <файл>`

Записывает числовой результат работы Конфигуратора в файл. Официальная документация указывает, что `0` означает успешное выполнение.

```bat
/DumpResult "<LOG_DIRECTORY>\designer.result"
```

### `/DisableStartupDialogs`

Запрещает диалоги авторизации и выбора параметров запуска. При недостаточных или неверных параметрах Конфигуратор завершится с ошибкой вместо ожидания действий пользователя.

Особенность хранилища: если данные авторизации хранилища не указаны, Конфигуратор запускается без подключения к хранилищу.

### `/DisableStartupMessages`

Отключает отдельные стартовые сообщения, в том числе вопрос о расхождении конфигурации базы данных и сохраняемой конфигурации.

### `/@ <файл команды>`

Позволяет вынести всю командную строку в один файл и обойти ограничение длины командной строки ОС.

Правила:

- `/@` должен быть первым или единственным параметром после имени приложения;
- содержимое файла полностью заменяет командную строку;
- вся команда в файле записывается в одну строку;
- кодировка должна соответствовать командному интерпретатору.

Пример запуска:

```bat
"<PLATFORM_EXECUTABLE>" /@ "<COMMAND_DIRECTORY>\designer-command.txt"
```

# 2. Выгрузка основной конфигурации и расширений в XML

## 2.1. Команда `/DumpConfigToFiles`

Назначение: выгрузить редактируемую конфигурацию или расширение в XML-файлы.

Официальный синтаксис:

```text
/DumpConfigToFiles <каталог выгрузки>
    [-Format <Plain|Hierarchical>]
    [-Extension <имя расширения>]
    [-AllExtensions]
    [-update]
    [-force]
    [-getChanges <имя файла>]
    [-configDumpInfoForChanges <полный путь к ConfigDumpInfo.xml>]
    [-listFile <имя файла>]
    [-configDumpInfoOnly]
    [-Server [-JobsCount <количество>]]
    [-Archive <имя ZIP-файла>]
    [-ignoreUnresolvedReferences]
```

## 2.2. Полная выгрузка основной конфигурации

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /Out "<PROJECT_ROOT>\logs\dump-main.log" ^
  /DumpResult "<PROJECT_ROOT>\logs\dump-main.result" ^
  /DumpConfigToFiles "<PROJECT_ROOT>\xml\main" ^
  -Format Hierarchical
```

### `-Format Plain`

Линейный формат выгрузки.

```bat
-Format Plain
```

### `-Format Hierarchical`

Иерархический формат. В 8.3.27 используется по умолчанию.

```bat
-Format Hierarchical
```

Для автоматизированной разработки следует один раз выбрать формат каталога и не менять его без полной повторной выгрузки.

## 2.3. Полная выгрузка одного расширения

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /Out "<PROJECT_ROOT>\logs\dump-extension.log" ^
  /DumpResult "<PROJECT_ROOT>\logs\dump-extension.result" ^
  /DumpConfigToFiles "<PROJECT_ROOT>\xml\Example_Refinement" ^
  -Extension "Example_Refinement" ^
  -Format Hierarchical
```

`-Extension` выбирает конкретное расширение по имени.

## 2.4. Выгрузка всех расширений

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\extensions" -AllExtensions
```

Каждое расширение выгружается в отдельный подкаталог с именем расширения. Основная конфигурация при `-AllExtensions` не выгружается.

> Нельзя одновременно использовать `-Extension` и `-AllExtensions`. Официальная документация прямо предупреждает, что поведение такой комбинации непредсказуемо.

## 2.5. Инкрементальная выгрузка: `-update`

### Что делает

`-update` обновляет существующий каталог выгрузки: выгружаются только объекты, версии которых отличаются от версий, записанных при предыдущей выгрузке.

Состояние предыдущей выгрузки хранится в:

```text
ConfigDumpInfo.xml
```

После успешной выгрузки файл обновляется.

### Пример основной конфигурации

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main" -update
```

### Пример расширения

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\Example_Refinement" ^
  -Extension "Example_Refinement" ^
  -update
```

### Когда `-update` нужно использовать

Используйте `-update`, когда одновременно выполнены условия:

1. Каталог уже содержит полную корректную выгрузку именно этой конфигурации или именно этого расширения.
2. В корне каталога есть `ConfigDumpInfo.xml`.
3. Формат предыдущей выгрузки совместим с текущей платформой и выбранным форматом.
4. Каталог не был частично заменён файлами из другой базы, другой конфигурации или другого расширения.
5. Требуется синхронизировать существующее дерево XML, а не создать независимую чистую выгрузку.

Типичный сценарий:

```text
полная выгрузка один раз → редактирование конфигурации → DumpConfigToFiles -update → анализ изменившихся XML
```

### Когда `-update` использовать нельзя или опасно

Не используйте `-update`, если:

- каталог пустой;
- отсутствует `ConfigDumpInfo.xml`;
- каталог скопирован неизвестно откуда;
- в каталоге находится выгрузка другой конфигурации или другого расширения;
- изменён формат `Plain`/`Hierarchical`;
- требуется гарантированно чистая эталонная выгрузка;
- предыдущая операция была прервана и целостность каталога не подтверждена;
- XML-файлы вручную удалялись или смешивались без понимания состояния `ConfigDumpInfo.xml`.

При отсутствии файла версий или несовпадении версии формата платформа завершает операцию с ошибкой.

## 2.6. `-force` вместе с `-update`

При обнаружении несовпадения версии формата выгрузки:

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main" -update -force
```

платформа выполняет полную выгрузку вместо инкрементальной.

Ограничение: `-force` имеет смысл только совместно с `-update`; в остальных случаях он игнорируется.

Рекомендация для строгого CI-процесса: не использовать `-force` автоматически, если важно отличать инкрементальное обновление от неожиданной полной перезаписи каталога. В таком процессе лучше завершить шаг ошибкой, очистить или перенести старый каталог и сделать отдельную полную выгрузку.

## 2.7. Получение списка изменений: `-getChanges`

Параметр записывает в указанный файл список отличий текущей конфигурации относительно состояния выгрузки.

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main" ^
  -update ^
  -getChanges "<PROJECT_ROOT>\logs\xml-changes.txt"
```

Сравнение выполняется относительно `ConfigDumpInfo.xml`, находящегося в каталоге выгрузки.

## 2.8. Сравнение с отдельным `ConfigDumpInfo.xml`

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\new-dump" ^
  -update ^
  -getChanges "<PROJECT_ROOT>\logs\changes.txt" ^
  -configDumpInfoForChanges "<PROJECT_ROOT>\baseline\ConfigDumpInfo.xml"
```

Особенности официального описания:

- `-configDumpInfoForChanges` применяется только вместе с `-update` и `-getChanges`;
- требуется полный путь к файлу;
- если файл не найден, возникает ошибка;
- перед выгрузкой целевой каталог должен быть пустым;
- файл, указанный в `-configDumpInfoForChanges`, не обновляется;
- в целевом каталоге создаётся новый файл версий.

## 2.9. Принудительная выгрузка перечисленных объектов: `-listFile`

Параметр задаёт файл со списком объектов, которые должны быть выгружены независимо от их статуса изменения.

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\selected" ^
  -listFile "<PROJECT_ROOT>\lists\dump-objects.txt"
```

Пример, прямо приведённый официальной документацией для свойств корневого объекта конфигурации:

```text
Configuration.Help
Configuration.ConfigurationName.Splash
```

Важные ограничения:

- подчинённые объекты, являющиеся самостоятельными объектами разработки, нужно указывать отдельно;
- внешние свойства несамостоятельных подчинённых объектов выгружаются вместе с объектом;
- официальная документация 8.3.27 указывает, что `-listFile` нельзя комбинировать с другими параметрами этой команды.

Из-за последнего ограничения не следует самостоятельно предполагать допустимость сочетаний `-listFile` с `-update`, `-force`, `-Server`, `-Archive` или другими необязательными ключами.

## 2.10. Создание только `ConfigDumpInfo.xml`

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\state-only" -configDumpInfoOnly
```

Разрешено дополнительно указать только формат:

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\state-only" ^
  -configDumpInfoOnly ^
  -Format Hierarchical
```

Сочетание с другими параметрами не поддерживается.

## 2.11. Выгрузка на стороне сервера

Для клиент-серверной базы:

```bat
/DumpConfigToFiles "<SERVER_ACCESSIBLE_DIRECTORY>\main" -Server
```

`-Server` переносит выгрузку на сторону сервера 1С и включает многопоточную обработку.

Число параллельных фоновых заданий:

```bat
-Server -JobsCount 4
```

`-JobsCount 0` означает автоматический выбор платформой на основании числа процессорных ядер сервера.

> Путь должен быть доступен процессу сервера 1С, а не только рабочей станции, с которой запущена команда.

## 2.12. Выгрузка в ZIP

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main" ^
  -Archive "<PROJECT_ROOT>\archives\main.zip"
```

Официально ZIP поддерживается для:

- полной выгрузки;
- частичной выгрузки;
- выгрузки только `ConfigDumpInfo.xml`;
- выгрузки всех расширений.

## 2.13. `-ignoreUnresolvedReferences`

Параметр исключает из XML недоступные ссылки на ранее удалённые объекты.

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main" -ignoreUnresolvedReferences
```

Это не универсальный способ «исправить» конфигурацию. Официальная документация предупреждает, что при последующей загрузке и сравнении могут появляться изменения объектов, в том числе без детализированного описания. Использовать параметр следует только при осознанной работе с недоступными ссылками.

# 3. Получение конфигурации из хранилища

## 3.1. Параметры доступа к хранилищу

### `/ConfigurationRepositoryF <каталог>`

Путь к хранилищу конфигурации.

```bat
/ConfigurationRepositoryF "<MAIN_REPOSITORY>"
```

### `/ConfigurationRepositoryN <имя>`

Имя пользователя хранилища.

```bat
/ConfigurationRepositoryN "<REPOSITORY_USER>"
```

### `/ConfigurationRepositoryP <пароль>`

Пароль пользователя хранилища.

```bat
/ConfigurationRepositoryP "<PASSWORD_FROM_SOURCE>"
```

В отличие от параметра пользователя информационной базы `/P`, официальный раздел о хранилище отдельно не описывает специальное правило для пустого пароля. Поэтому нельзя автоматически переносить правило «не указывать `/P`» на `/ConfigurationRepositoryP`. Для пустого пароля проверьте принятую в вашем окружении форму передачи пустого значения, например `/ConfigurationRepositoryP ""`, на конкретной сборке платформы и обязательно контролируйте `/Out`. В примерах ниже параметр опущен только потому, что официальный источник не фиксирует универсальный синтаксис пустого пароля хранилища.

## 3.2. Подключение основной конфигурации к хранилищу

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /ConfigurationRepositoryF "<MAIN_REPOSITORY>" ^
  /ConfigurationRepositoryN "<REPOSITORY_USER>" ^
  /ConfigurationRepositoryBindCfg
```

### `-forceBindAlreadyBindedUser`

Разрешает подключение, даже если для этого пользователя уже существует конфигурация, связанная с данным хранилищем.

### `-forceReplaceCfg`

Подтверждает замену непустой локальной конфигурации конфигурацией из хранилища.

```bat
/ConfigurationRepositoryBindCfg -forceReplaceCfg
```

Этот ключ может привести к замене текущего содержимого конфигурации. Его нельзя добавлять в общий скрипт «на всякий случай».

## 3.3. Подключение расширения к отдельному хранилищу

Расширение указывается параметром `-Extension`:

```bat
/ConfigurationRepositoryF "<EXTENSION_REPOSITORY>" ^
/ConfigurationRepositoryN "<REPOSITORY_USER>" ^
/ConfigurationRepositoryBindCfg ^
-Extension "Example_Refinement"
```

Если `-Extension` не указан, команда относится к основной конфигурации.

## 3.4. Получение последней версии основной конфигурации

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /DisableStartupMessages ^
  /ConfigurationRepositoryF "<MAIN_REPOSITORY>" ^
  /ConfigurationRepositoryN "<REPOSITORY_USER>" ^
  /ConfigurationRepositoryUpdateCfg ^
  -force ^
  /Out "<PROJECT_ROOT>\logs\repository-update-main.log" ^
  /DumpResult "<PROJECT_ROOT>\logs\repository-update-main.result"
```

## 3.5. Получение расширения из его хранилища

```bat
/ConfigurationRepositoryF "<EXTENSION_REPOSITORY>" ^
/ConfigurationRepositoryN "<REPOSITORY_USER>" ^
/ConfigurationRepositoryUpdateCfg ^
-force ^
-Extension "Example_Refinement"
```

Основная конфигурация и каждое расширение обрабатываются отдельными командами. Обновление основной конфигурации не означает автоматическое обновление всех хранилищ расширений.

## 3.6. Параметры `ConfigurationRepositoryUpdateCfg`

Официальный синтаксис:

```text
/ConfigurationRepositoryUpdateCfg
    [-v <номер версии хранилища>]
    [-revised]
    [-force]
    [-Objects <файл списка объектов>]
    [-Extension <имя расширения>]
```

### `-v <номер>`

Для подключённой к хранилищу конфигурации номер версии игнорируется, получается актуальная версия хранилища. Если конфигурация не подключена, может быть получена указанная версия; при отсутствии номера или значении `-1` получается текущая версия.

Это поведение дополнительно сверено по официальной испанской версии документации 8.3.27, поскольку английский текст страницы содержит явную повторную фразу в условии.

### `-revised`

Получать захваченные объекты, когда это требуется. Если конфигурация не подключена к хранилищу, параметр игнорируется.

### `-force`

Подтверждает получение новых объектов и удаление объектов, которые изменились в составе хранилища. Без `-force` такие действия пропускаются.

Практический вывод: обновление без `-force` может формально завершиться, но не применить добавление или удаление объектов. Поэтому результат нужно проверять по `/Out`, а не только по коду завершения.

### `-Objects <файл>`

Ограничивает операцию объектами из файла. Без ключа участвует вся конфигурация.

```bat
/ConfigurationRepositoryUpdateCfg -Objects "<PROJECT_ROOT>\lists\repository-objects.txt"
```

Формат файла определён официальным приложением «Object list file». Не следует подменять его списком путей XML: список объектов хранилища и список XML-файлов для `LoadConfigFromFiles` - разные форматы и разные сущности.

## 3.7. Инкрементальное получение из хранилища

У команды хранилища нет документированного ключа `-update`, аналогичного XML-выгрузке.

Есть два сценария:

1. **Обычное обновление всей подключённой конфигурации** - `ConfigurationRepositoryUpdateCfg` без `-Objects`. Платформа приводит локальную конфигурацию к актуальному состоянию хранилища, но область операции формально охватывает всю конфигурацию.
2. **Выборочное обновление** - `ConfigurationRepositoryUpdateCfg -Objects <файл>`. Операция ограничена явно перечисленными объектами.

`-Objects` не означает «автоматически найти всё изменённое». Это заранее заданный список объектов.

## 3.8. Как проверить, подключена ли конфигурация или расширение к хранилищу

В официальном перечне пакетных команд 8.3.27 **нет отдельной недеструктивной команды**, которая возвращает булево состояние «подключена/не подключена».

Нельзя считать доказательством подключения:

- успешное чтение отчёта хранилища - оно подтверждает доступ к хранилищу, но не локальную привязку конфигурации;
- наличие расширения в `/DumpDBCfgList` - команда подтверждает существование расширения, но не подключение его к хранилищу;
- наличие параметров `/ConfigurationRepositoryF/N/P` - это только переданные реквизиты доступа.

Надёжные варианты:

1. Проверить состояние интерактивно в Конфигураторе.
2. В автоматизированном процессе хранить факт выполненного `ConfigurationRepositoryBindCfg` как состояние среды развертывания.
3. Выполнять требуемую операцию хранилища и анализировать `/Out`; ошибка отсутствия подключения является диагностикой конкретного запуска, но текст сообщения нельзя заменять придуманным универсальным кодом.

Не следует использовать для проверки `ConfigurationRepositoryUnbindCfg`: это изменяющая и потенциально разрушительная операция.

# 4. Загрузка XML в конфигурацию и расширение

## 4.1. Команда `/LoadConfigFromFiles`

Назначение: восстановить конфигурацию из XML-файлов.

Состав параметров:

```text
/LoadConfigFromFiles <каталог загрузки>
    [-Extension <имя расширения>]
    [-AllExtensions]
    [-files "<файл1>,<файл2>,..."]
    [-listFile <файл списка>]
    [-Format <Plain|Hierarchical>]
    [-updateConfigDumpInfo]
    [-NoCheck]
    [-Archive <ZIP-архив>]
    [-partial]
```

## 4.2. Полная загрузка основной конфигурации

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /Out "<PROJECT_ROOT>\logs\load-main.log" ^
  /DumpResult "<PROJECT_ROOT>\logs\load-main.result" ^
  /LoadConfigFromFiles "<PROJECT_ROOT>\xml\main"
```

При полной загрузке платформа автоматически определяет линейный или иерархический формат.

## 4.3. Полная загрузка расширения

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\Example_Refinement" ^
  -Extension "Example_Refinement"
```

Если расширение не существует, оно создаётся с указанным именем.

Ограничение: если расширение подключено к хранилищу, полная загрузка в него запрещена.

## 4.4. Загрузка всех расширений

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\extensions" -AllExtensions
```

Каждый подкаталог рассматривается как отдельное расширение.

`-AllExtensions` несовместим с `-files` и `-listFile`.

## 4.5. Частичная загрузка через `-files`

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\main" ^
  -files "Catalogs\Номенклатура.xml,Catalogs\Номенклатура\Forms\ФормаЭлемента.xml" ^
  -Format Hierarchical
```

Правила:

- список заключается в кавычки;
- имена разделяются запятыми;
- допускаются полные пути или пути относительно каталога загрузки;
- при частичной загрузке формат нужно указать явно;
- `-files` несовместим с `-AllExtensions`.

Пути выше являются примером структуры иерархической выгрузки. В рабочем скрипте нужно использовать точные относительные пути, существующие в конкретном каталоге выгрузки.

## 4.6. Частичная загрузка через `-listFile`

Команда:

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\main" ^
  -listFile "<PROJECT_ROOT>\lists\load-files.txt" ^
  -Format Hierarchical
```

Пример содержимого `load-files.txt`:

```text
Catalogs\Номенклатура.xml
Catalogs\Номенклатура\Forms\ФормаЭлемента.xml
Catalogs\Номенклатура\Forms\ФормаЭлемента\Ext\Form\Module.bsl
```

Требования официальной документации:

- один путь на строку;
- путь полный или относительный к каталогу загрузки;
- кодировка UTF-8;
- окончания строк Windows и Linux поддерживаются;
- пустые строки не поддерживаются;
- строки, начинающиеся с `REM`, пропускаются;
- параметр несовместим с `-AllExtensions`.

Если одновременно указаны `-files` и `-listFile`, используется тот параметр, который встретился первым в командной строке. Для предсказуемого скрипта нельзя указывать оба.

## 4.7. Параметр `-partial`

`-partial` загружает только ту часть описания объекта, которая представлена конкретным файлом. Поддерживаются, в частности:

- файл описания объекта без внешних свойств;
- файл внешнего свойства, например формы;
- файл модуля формы без файла описания формы.

Пример точечной загрузки только файла модуля:

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\main" ^
  -files "Catalogs\Номенклатура\Forms\ФормаЭлемента\Ext\Form\Module.bsl" ^
  -Format Hierarchical ^
  -partial
```

Использование `-partial` особенно важно для автоматического изменения одного внешнего свойства, когда не требуется заменять весь объект описанием из выгрузки.

## 4.8. Частичная загрузка в расширение, подключённое к хранилищу

Официальная документация допускает частичную загрузку при условии, что загружаемые объекты захвачены в хранилище расширения.

Правильная последовательность:

1. Захватить нужные объекты командой `ConfigurationRepositoryLock -Extension ...`.
2. Выполнить частичную `LoadConfigFromFiles -Extension ...`.
3. Проверить расширение.
4. При необходимости обновить конфигурацию базы данных расширения.
5. Поместить изменения командой `ConfigurationRepositoryCommit -Extension ...`.

## 4.9. `-updateConfigDumpInfo`

После загрузки создаёт соответствующий текущей конфигурации `ConfigDumpInfo.xml` в каталоге загрузки.

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\main" -updateConfigDumpInfo
```

При частичной загрузке обновляется существующий файл версий.

Использовать параметр следует, когда каталог XML должен остаться синхронизированным с загруженной конфигурацией и затем использоваться для `DumpConfigToFiles -update`.

## 4.10. `-NoCheck`

Отключает проверку целостности загружаемой конфигурации и сокращает время загрузки.

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\main" -NoCheck
```

Официальная документация рекомендует этот ключ только тогда, когда инициатор уверен в целостности загружаемой конфигурации. В универсальном агентском или CI-скрипте не следует включать его по умолчанию.

## 4.11. Загрузка из ZIP

Вместо каталога можно указать архив:

```bat
/LoadConfigFromFiles -Archive "<PROJECT_ROOT>\archives\main.zip"
```

Нельзя одновременно указывать каталог загрузки и `-Archive`.

## 4.12. Нельзя загрузить расширение в основную конфигурацию

Платформа не поддерживает:

- загрузку XML основной конфигурации в расширение;
- загрузку XML расширения в основную конфигурацию.

Корневой тип выгрузки должен соответствовать целевому объекту.

## 4.13. Отличие `/LoadConfigFiles`

```text
/LoadConfigFiles <каталог>
    [-Module]
    [-Template]
    [-Help]
    [-AllWritable]
    [-Picture]
    [-Right]
    [-Extension <имя>]
```

Команда загружает отдельные свойства объектов, а не полноценное XML-представление конфигурации.

Параметры:

- `-Module` - модули;
- `-Template` - макеты;
- `-Help` - справочная информация;
- `-AllWritable` - только свойства доступных для записи объектов;
- `-Picture` - общие картинки;
- `-Right` - права;
- `-Extension` - свойства указанного расширения.

Если расширение подключено к хранилищу, импортируемые объекты должны быть захвачены.

# 5. Обновление конфигурации базы данных

## 5.1. Команда `/UpdateDBCfg`

Назначение: обновить конфигурацию базы данных по текущей редактируемой конфигурации.

Официальный синтаксис:

```text
/UpdateDBCfg
    [-Dynamic<+|->]
    [-BackgroundStart]
    [-BackgroundCancel]
    [-BackgroundFinish [-Visible]]
    [-BackgroundSuspend]
    [-BackgroundResume]
    [-WarningsAsErrors]
    [-Server]
    [-v1|-v2]
    [-Extension <имя расширения>]
    [-SessionTerminate <disable|force>]
```

## 5.2. Обычное обновление основной конфигурации

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /Out "<PROJECT_ROOT>\logs\update-db.log" ^
  /DumpResult "<PROJECT_ROOT>\logs\update-db.result" ^
  /UpdateDBCfg -Dynamic-
```

`-Dynamic-` явно запрещает динамическое обновление.

## 5.3. Разрешение динамического обновления

```bat
/UpdateDBCfg -Dynamic+
```

Алгоритм платформы:

1. Сначала выполняется попытка обычного обновления.
2. Если обычное обновление невозможно, выполняется попытка динамического обновления.

Динамическое обновление также разрешено, если:

- `-Dynamic+` не указан;
- указан `-Dynamic` без режима.

Следовательно, отсутствие `-Dynamic-` не означает «только обычное обновление».

## 5.4. Что делать, если динамическое обновление не выполнилось

Рекомендуемая последовательность:

1. Прочитать `/Out` и определить причину.
2. Если требуется монопольный режим, завершить пользовательские сеансы управляемым административным способом.
3. Повторить обновление с запретом динамического режима:

```bat
/UpdateDBCfg -Dynamic-
```

4. Если допустимо принудительно завершить активные сеансы при запросе монопольной блокировки:

```bat
/UpdateDBCfg -Dynamic- -SessionTerminate force
```

`-SessionTerminate force` может принудительно завершить активные сеансы. Этот режим нельзя применять без понимания влияния на пользователей и фоновые задания.

Значение по умолчанию:

```bat
-SessionTerminate disable
```

## 5.5. Обновление расширения

```bat
/UpdateDBCfg -Extension "Example_Refinement" -Dynamic+
```

Команда обновляет конфигурацию базы данных указанного расширения.

## 5.6. Выполнение реструктуризации на сервере

```bat
/UpdateDBCfg -Server -Dynamic-
```

`-Server` применим для клиент-серверной базы и переносит обновление на сервер 1С.

## 5.7. Механизм реструктуризации `-v1` и `-v2`

```bat
/UpdateDBCfg -v1
```

или:

```bat
/UpdateDBCfg -v2
```

Если механизм явно не задан, используется значение `UpdateDBCfg` из клиентского `conf.cfg`.

Ограничения:

- для фонового обновления выбор `-v1/-v2` игнорируется;
- при `-Server` оптимизированный механизм не используется, `-v2` может быть проигнорирован;
- если выбранный механизм несовместим с другими параметрами, платформа использует обычный механизм.

## 5.8. Предупреждения как ошибки

```bat
/UpdateDBCfg -WarningsAsErrors
```

Без этого ключа диагностические сообщения считаются предупреждениями и сами по себе не блокируют обновление.

## 5.9. Фоновое обновление

### Запуск

```bat
/UpdateDBCfg -BackgroundStart
```

Команда запускает фоновое обновление и завершает работу Конфигуратора.

Если одновременно разрешено динамическое обновление, сначала выполняется динамическая попытка, а при неудаче запускается фоновое обновление.

### Приостановка

```bat
/UpdateDBCfg -BackgroundSuspend
```

### Продолжение

```bat
/UpdateDBCfg -BackgroundResume
```

### Отмена

```bat
/UpdateDBCfg -BackgroundCancel
```

### Завершение и принятие изменений

```bat
/UpdateDBCfg -BackgroundFinish
```

Платформа пытается получить монопольный доступ и выполнить финальную фазу. `-Visible` выводит интерактивный диалог и поэтому не подходит для полностью безоператорного pipeline.

## 5.10. Совмещение с предыдущей командой

Официально `/UpdateDBCfg` разрешено использовать после:

- `/LoadCfg`;
- `/UpdateCfg`;
- `/ConfigurationRepositoryUpdateCfg`;
- `/LoadConfigFiles`;
- `/LoadConfigFromFiles`;
- ряда мобильных команд.

Пример «загрузить XML и обновить базу» одним запуском:

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\main" ^
/UpdateDBCfg -Dynamic+
```

Пример «получить из хранилища и обновить базу»:

```bat
/ConfigurationRepositoryUpdateCfg -force ^
/UpdateDBCfg -Dynamic+
```

Это является явно документированным исключением из общего правила, что большинство пакетных команд нельзя произвольно объединять в одном запуске.

# 6. Захват, помещение и отмена захвата объектов

## 6.1. Захват объектов: `/ConfigurationRepositoryLock`

```text
/ConfigurationRepositoryLock
    [-Objects <файл списка объектов>]
    [-revised]
    [-Extension <имя расширения>]
```

### Основная конфигурация

```bat
/ConfigurationRepositoryF "<MAIN_REPOSITORY>" ^
/ConfigurationRepositoryN "<REPOSITORY_USER>" ^
/ConfigurationRepositoryLock ^
-Objects "<PROJECT_ROOT>\lists\repository-objects.txt"
```

### Расширение

```bat
/ConfigurationRepositoryLock ^
-Objects "<PROJECT_ROOT>\lists\extension-objects.txt" ^
-Extension "Example_Refinement"
```

`-revised` дополнительно получает захваченные объекты, когда это необходимо.

Без `-Objects` команда относится ко всей конфигурации. Для рабочего процесса разработчика почти всегда следует задавать список, чтобы не пытаться захватить всю конфигурацию.

## 6.2. Помещение изменений: `/ConfigurationRepositoryCommit`

```text
/ConfigurationRepositoryCommit
    [-Objects <файл списка объектов>]
    [-comment <текст>]
    [-keepLocked]
    [-force]
    [-Extension <имя расширения>]
```

Пример основной конфигурации:

```bat
/ConfigurationRepositoryCommit ^
  -Objects "<PROJECT_ROOT>\lists\repository-objects.txt" ^
  -comment "Добавлен реквизит Example_Вес" ^
  -keepLocked
```

Пример расширения:

```bat
/ConfigurationRepositoryCommit ^
  -Objects "<PROJECT_ROOT>\lists\extension-objects.txt" ^
  -comment "Обновлена форма документа" ^
  -Extension "Example_Refinement"
```

### `-comment`

Комментарий заключается в двойные кавычки. Для многострочного комментария каждая строка передаётся отдельным параметром:

```bat
-comment "Первая строка" -comment "Вторая строка"
```

### `-keepLocked`

После помещения сохраняет захват. Без него объекты освобождаются.

### `-force`

Если обнаружены ссылки на удалённые объекты, платформа пытается удалить ссылки. Без `-force` формируется ошибка.

Это не безусловное разрешение на удаление: лог необходимо проверить.

## 6.3. Отмена захвата: `/ConfigurationRepositoryUnLock`

```text
/ConfigurationRepositoryUnLock
    [-Objects <файл списка объектов>]
    [-force]
    [-Extension <имя расширения>]
```

Пример:

```bat
/ConfigurationRepositoryUnLock ^
  -Objects "<PROJECT_ROOT>\lists\repository-objects.txt"
```

### Опасность `-force`

```bat
/ConfigurationRepositoryUnLock -force
```

Если объекты изменены локально, они будут получены из хранилища, а локальные изменения потеряются.

Без `-force` наличие локальных изменений приводит к ошибке и отмене всей операции для перечисленных объектов.

## 6.4. Рекомендуемый рабочий цикл

```text
1. Проверить источник и права: при repository получить актуальную версию разрешённой синхронизацией; при working_configuration не получать ради baseline
2. Выгрузить XML рабочей конфигурации Конфигуратора через DumpConfigToFiles
3. Проанализировать свежие XML и зафиксировать изменяемые объекты
4. ConfigurationRepositoryLock -Objects ...
5. Изменить запланированные XML или рабочую конфигурацию
6. LoadConfigFromFiles -files/-listFile -Format ...; -partial только для части объекта
7. Проверить результат средствами, разрешёнными AGENTS.md проекта
8. UpdateDBCfg только при необходимости и разрешении
9. Повторно выгрузить рабочую конфигурацию без -getChanges и выполнить функциональное тестирование
10. ConfigurationRepositoryCommit -Objects ... -comment ... при наличии разрешения
```

Для расширения на всех соответствующих командах добавляется:

```text
-Extension "ИмяРасширения"
```

Путь и учётные данные должны указывать на хранилище именно этого расширения.

# 7. Проверка конфигурации перед помещением

## 7.1. Проверка модулей

```text
/CheckModules
    [-ThinClient]
    [-WebClient]
    [-MobileClient]
    [-MobileAppClient]
    [-Server]
    [-MobileAppServer]
    [-ExternalConnection]
    [-ThickClientOrdinaryApplication]
    [-ExtendedModulesCheck]
    [-Extension <имя>]
    [-AllExtensions]
```

Нужно указать хотя бы один режим проверки, иначе проверка не выполняется.

Пример основной конфигурации:

```bat
/CheckModules -Server -ThinClient -ExtendedModulesCheck
```

Пример расширения:

```bat
/CheckModules -Server -ThinClient -Extension "Example_Refinement"
```

## 7.2. Централизованная проверка конфигурации

Минимальная полезная проверка перед обновлением базы:

```bat
/CheckConfig -ConfigLogIntegrity -IncorrectReferences -Server -ThinClient
```

Для расширения:

```bat
/CheckConfig ^
  -ConfigLogIntegrity ^
  -IncorrectReferences ^
  -Server ^
  -ThinClient ^
  -Extension "Example_Refinement"
```

Набор режимов должен соответствовать реальной архитектуре конфигурации. Не следует механически включать мобильные, веб- и обычные режимы, если они не используются.

## 7.3. Проверка применимости расширения

```bat
/CheckCanApplyConfigurationExtensions -Extension "Example_Refinement"
```

Команда проверяет, может ли расширение применяться к конкретной информационной базе с учётом ранее загруженных расширений.

# 8. Возвращаемые результаты и их интерпретация

## 8.1. Что нужно собирать после каждого запуска

Автоматизация должна проверять четыре независимых источника:

1. Код завершения процесса `1cv8.exe`.
2. Содержимое файла `/DumpResult`.
3. Содержимое файла `/Out`.
4. Фактический ожидаемый результат: наличие файлов, изменение `ConfigDumpInfo.xml`, создание версии хранилища и т. п.

Опираться только на наличие процесса или только на один файл нельзя.

## 8.2. Документированные коды

### Операции с расширениями

Для команд с `-Extension`/`-AllExtensions` официальная документация указывает:

- `0` - успешно;
- `1` - ошибка.

### Захват, отмена захвата и помещение в хранилище

Для `ConfigurationRepositoryLock`, `ConfigurationRepositoryUnLock` и `ConfigurationRepositoryCommit`:

- `0` - ошибок нет;
- `1` - есть ошибки, текст находится в файле служебных сообщений.

### `DumpConfigFiles` / `LoadConfigFiles`

Официально:

- `0` - успешно;
- `1` - ошибка;
- `101` - данные содержат ошибки.

Нельзя автоматически распространять код `101` на все остальные команды, если это прямо не указано для конкретной команды.

### `/DumpResult`

Число `0` означает успешное выполнение операции. При другом значении следует анализировать `/Out`.

## 8.3. Пример проверки в PowerShell

```powershell
$OneC = '<PLATFORM_EXECUTABLE>'
$Log = '<PROJECT_ROOT>\logs\dump.log'
$Result = '<PROJECT_ROOT>\logs\dump.result'
$Target = '<PROJECT_ROOT>\xml\main'

Remove-Item -LiteralPath $Log, $Result -Force -ErrorAction SilentlyContinue

& $OneC DESIGNER `
    /S '<SERVER>\<INFOBASE>' `
    /WA+ `
    /DisableStartupDialogs `
    /DisableStartupMessages `
    /Out $Log `
    /DumpResult $Result `
    /DumpConfigToFiles $Target `
    -update

$ExitCode = $LASTEXITCODE
$DesignerResult = if (Test-Path -LiteralPath $Result) {
    (Get-Content -LiteralPath $Result -Raw).Trim()
} else {
    $null
}

if ($ExitCode -ne 0 -or $DesignerResult -ne '0') {
    $LogText = if (Test-Path -LiteralPath $Log) {
        Get-Content -LiteralPath $Log -Raw
    } else {
        '<файл лога не создан>'
    }

    throw "Пакетная операция 1С завершилась ошибкой. ExitCode=$ExitCode; DumpResult=$DesignerResult`n$LogText"
}

if (-not (Test-Path -LiteralPath (Join-Path $Target 'ConfigDumpInfo.xml'))) {
    throw 'Операция сообщила об успехе, но ConfigDumpInfo.xml не найден.'
}
```

Проверка фактического результата нужна на случай неверного пути, ошибки окружения или ошибочного предположения о том, что конкретная команда должна была создать файл.

# 9. Типовые ошибки и действия

## 9.1. Каталог по полному пути не существует

**Причина:** для параметра указан полный путь, но один из родительских каталогов отсутствует.

**Официальное поведение:** операция завершается ошибкой.

**Действие:** до запуска создать родительские каталоги:

```powershell
New-Item -ItemType Directory -Path '<PROJECT_ROOT>\logs' -Force | Out-Null
New-Item -ItemType Directory -Path '<PROJECT_ROOT>\xml\main' -Force | Out-Null
```

## 9.2. Конфигуратор открыл окно и ждёт пользователя

**Причины:**

- не указана база;
- недостаточно данных авторизации;
- не указан `/DisableStartupDialogs`;
- возник стартовый вопрос;
- команда запущена с `/Visible`.

**Действие:** задать `/F` или `/S`, авторизацию, `/DisableStartupDialogs`, `/DisableStartupMessages`, `/Out`.

## 9.3. Неверное цитирование команды в Windows

Неверно для `cmd.exe`:

```text
'<PLATFORM_EXECUTABLE>' DESIGNER ...
```

Одинарные кавычки не являются штатным способом экранирования пути в `cmd.exe`.

Правильно:

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ...
```

В PowerShell:

```powershell
& '<PLATFORM_EXECUTABLE>' DESIGNER ...
```

## 9.4. `-update`: отсутствует `ConfigDumpInfo.xml`

**Причина:** каталог не является предыдущей полной выгрузкой или файл удалён.

**Действие:** не создавать фиктивный файл вручную. Выполнить полную выгрузку в чистый каталог.

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main-new" -Format Hierarchical
```

## 9.5. `-update`: несовместима версия формата

**Действия:**

- строгий вариант - остановить pipeline и сделать новую полную выгрузку в другой каталог;
- разрешённый платформой вариант - повторить с `-update -force`, понимая, что будет выполнена полная выгрузка.

## 9.6. Смешаны `-Extension` и `-AllExtensions`

**Официальное предупреждение:** поведение непредсказуемо.

**Действие:** завершить скрипт до запуска; параметры должны быть взаимоисключающими.

## 9.7. Полная загрузка расширения, подключённого к хранилищу

**Причина:** полная `LoadConfigFromFiles -Extension` для такого расширения не поддерживается.

**Действие:** захватить нужные объекты и выполнить частичную загрузку перечисленных XML-файлов либо временно изменить организацию работы с хранилищем осознанной административной процедурой.

## 9.8. Частичная загрузка без `-Format`

**Причина:** при частичной загрузке формат автоматически не определяется.

**Действие:** явно задать:

```bat
-Format Hierarchical
```

или:

```bat
-Format Plain
```

в соответствии с фактической выгрузкой.

## 9.9. Использован `-AllExtensions` вместе с `-files` или `-listFile`

Комбинация не поддерживается.

**Действие:** загружать все расширения полностью либо выполнять отдельный запуск для конкретного расширения.

## 9.10. XML основной конфигурации загружается в расширение или наоборот

Комбинация не поддерживается.

**Действие:** проверить корневой каталог выгрузки и значение `-Extension`.

## 9.11. Обновление из хранилища не добавило или не удалило объекты

Возможная причина: отсутствует `-force`.

Официальное поведение: действия по получению новых и удалению существующих объектов пропускаются без подтверждающего ключа.

**Действие:** изучить `/Out`, после чего повторить с `-force`, если изменения ожидаемы и допустимы.

## 9.12. Неверные реквизиты хранилища при `/DisableStartupDialogs`

**Поведение:** вместо интерактивного запроса формируется ошибка. Если реквизиты хранилища вообще не указаны, Конфигуратор запускается без подключения к хранилищу.

**Действие:** передать корректные `/ConfigurationRepositoryF`, `/ConfigurationRepositoryN`, `/ConfigurationRepositoryP` и проверить доступ процесса к каталогу.

## 9.13. Не удалось получить монопольный доступ при `UpdateDBCfg`

**Действия:**

1. Проверить активные сеансы и фоновые задания.
2. Предупредить пользователей.
3. Повторить обычное обновление с `-Dynamic-`.
4. При утверждённой политике обслуживания использовать `-SessionTerminate force`.

Нельзя автоматически завершать пользовательские сеансы без согласованного окна обслуживания.

## 9.14. Динамическое обновление прошло, но часть сеансов продолжает работать по старой конфигурации

Официальное руководство разработчика указывает: пользователи, работавшие в момент динамического обновления, продолжают работать со старой конфигурацией; для перехода на обновлённую конфигурацию им требуется перезапустить приложение 1С. Поэтому успешный код пакетной команды не означает, что все уже открытые сеансы немедленно используют новые метаданные. Необходимость последующего обычного обновления определяется составом изменений и регламентом эксплуатации базы.

## 9.15. Локальные изменения будут потеряны при `ConfigurationRepositoryUnLock -force`

**Причина:** `-force` получает объект из хранилища поверх локальных изменений.

**Действие:** перед запуском сохранить изменения или поместить их. В автоматизации требовать отдельное явное разрешение на этот ключ.

## 9.16. Модули закрыты паролем

Официальное поведение пакетного режима: модули, защищённые паролем, игнорируются; формируется диагностическое сообщение.

**Действие:** анализировать `/Out`. Нельзя считать выгрузку или проверку полной, если требуемые модули были пропущены.

## 9.17. Лог содержит предупреждения, но код равен нулю

Некоторые операции допускают предупреждения. Для `UpdateDBCfg` можно использовать:

```bat
-WarningsAsErrors
```

Однако автоматический анализ должен различать:

- предупреждение, которое допустимо по политике проекта;
- предупреждение о пропущенном действии;
- ошибку целостности или невозможности обновления.

Универсального официального списка всех текстов ошибок для этих команд нет; главным источником диагностики является `/Out` конкретного запуска.

# 10. Готовые сценарии

## 10.1. Получить основную конфигурацию из хранилища и обновить базу

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /DisableStartupMessages ^
  /ConfigurationRepositoryF "<MAIN_REPOSITORY>" ^
  /ConfigurationRepositoryN "<REPOSITORY_USER>" ^
  /ConfigurationRepositoryUpdateCfg ^
  -force ^
  /UpdateDBCfg -Dynamic+ ^
  /Out "<PROJECT_ROOT>\logs\update-from-repository.log" ^
  /DumpResult "<PROJECT_ROOT>\logs\update-from-repository.result"
```

## 10.2. Получить расширение из хранилища и обновить его в базе

```bat
"<PLATFORM_EXECUTABLE>" DESIGNER ^
  /S "<SERVER>\<INFOBASE>" ^
  /WA+ ^
  /DisableStartupDialogs ^
  /ConfigurationRepositoryF "<EXTENSION_REPOSITORY>" ^
  /ConfigurationRepositoryN "<REPOSITORY_USER>" ^
  /ConfigurationRepositoryUpdateCfg ^
  -force ^
  -Extension "Example_Refinement" ^
  /UpdateDBCfg ^
  -Dynamic+ ^
  -Extension "Example_Refinement" ^
  /Out "<PROJECT_ROOT>\logs\update-extension.log" ^
  /DumpResult "<PROJECT_ROOT>\logs\update-extension.result"
```

У каждого из двух пакетных действий собственный `-Extension`. Нельзя рассчитывать, что параметр автоматически «перейдёт» от одной команды к другой без явного указания.

## 10.3. Полная первая XML-выгрузка и последующие инкрементальные выгрузки

Первая выгрузка:

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main" -Format Hierarchical
```

Последующие:

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main" ^
  -update
```

Для самостоятельного списка отличий используют отдельный диагностический запуск:

```bat
/DumpConfigToFiles "<PROJECT_ROOT>\xml\main" ^
  -update ^
  -getChanges "<PROJECT_ROOT>\logs\changes.txt"
```

Режим `-getChanges` не обновляет XML. Для свежего baseline и контрольной выгрузки после
изменения нужна команда без этого параметра и проверка фактических файлов.

## 10.4. Загрузить только изменённые XML-файлы

`load-files.txt`:

```text
CommonModules\Example_ОбщийМодуль.xml
CommonModules\Example_ОбщийМодуль\Ext\Module.bsl
Catalogs\Example_Задачи.xml
Catalogs\Example_Задачи\Forms\ФормаЭлемента.xml
```

Команда:

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\main" ^
  -listFile "<PROJECT_ROOT>\lists\load-files.txt" ^
  -Format Hierarchical ^
  -partial ^
  -updateConfigDumpInfo ^
/UpdateDBCfg -Dynamic+
```

Перед использованием нужно убедиться, что пути существуют в выгрузке и соответствуют изменяемым внешним свойствам.

## 10.5. Захватить объекты, загрузить XML и поместить в хранилище

Шаг 1 - захват:

```bat
/ConfigurationRepositoryLock ^
  -Objects "<PROJECT_ROOT>\lists\repository-objects.txt"
```

Шаг 2 - частичная загрузка:

```bat
/LoadConfigFromFiles "<PROJECT_ROOT>\xml\main" ^
  -listFile "<PROJECT_ROOT>\lists\load-files.txt" ^
  -Format Hierarchical ^
  -partial
```

Шаг 3 - проверка:

```bat
/CheckConfig -ConfigLogIntegrity -IncorrectReferences -Server -ThinClient
```

Шаг 4 - обновление базы:

```bat
/UpdateDBCfg -Dynamic+
```

Шаг 5 - помещение:

```bat
/ConfigurationRepositoryCommit ^
  -Objects "<PROJECT_ROOT>\lists\repository-objects.txt" ^
  -comment "Описание выполненной доработки"
```

Для надёжной диагностики каждый логически самостоятельный этап рекомендуется запускать отдельным процессом 1С с отдельными `/Out` и `/DumpResult`. Исключение - официально разрешённые связки загрузки/получения конфигурации с последующим `/UpdateDBCfg`.

# 11. Контрольный список перед запуском

## Перед XML-выгрузкой

- [ ] Запускается именно `1cv8.exe` версии 8.3.27.
- [ ] База указана через `/S` или `/F`.
- [ ] Авторизация не требует диалога.
- [ ] Все родительские каталоги существуют.
- [ ] Для `-update` существует корректный `ConfigDumpInfo.xml`.
- [ ] Не смешаны `-Extension` и `-AllExtensions`.
- [ ] Каталог принадлежит нужной конфигурации или расширению.

## Перед XML-загрузкой

- [ ] Основная конфигурация не перепутана с расширением.
- [ ] Для частичной загрузки указан `-Format`.
- [ ] Файл списка в UTF-8, без пустых строк.
- [ ] Для подключённого к хранилищу расширения объекты захвачены.
- [ ] `-NoCheck` используется только при подтверждённой целостности.

## Перед обновлением базы

- [ ] Результат загрузки или получения из хранилища успешен.
- [ ] Выполнена проверка модулей/конфигурации.
- [ ] Понятно, допускается ли динамическое обновление.
- [ ] Согласована политика завершения сеансов.
- [ ] Созданы отдельные файлы `/Out` и `/DumpResult`.

## Перед помещением в хранилище

- [ ] Помещаются только нужные объекты.
- [ ] Объекты захвачены текущим пользователем.
- [ ] Конфигурация базы данных обновлена и протестирована.
- [ ] Комментарий описывает изменение.
- [ ] `-force` и `-keepLocked` применяются осознанно.

## 13. Зафиксированные ограничения достоверности

1. В официальном перечне команд нет отдельного ключа для прямой проверки факта подключения конфигурации к хранилищу. В документе это не заменено выдуманной командой.
2. Официальная страница приложения с форматом файла списка объектов хранилища в публичном интерфейсе может отображаться без содержимого. Поэтому документ не придумывает формат этого файла и ссылается на официальное приложение.
3. Тексты конкретных сообщений об ошибках зависят от ситуации, локализации и состояния базы. В документе приведены подтверждённые причины и действия, но не выдуман универсальный каталог строк ошибок.
4. Код `101` указан только там, где он прямо документирован - для `DumpConfigFiles`/`LoadConfigFiles`. Он не объявлен универсальным кодом всех пакетных команд.
5. Примеры относительных путей XML нужно сверять с фактическим деревом конкретной выгрузки.
