# 1C Configurator Batch 8.3.27

Обезличенный полный комплект навыка документированных операций пакетного режима
Конфигуратора 1С:Предприятие 8.3.27. Название навыка и каталога -
`1c-configurator-batch-8-3-27`.

## Состав

- `SKILL.md` - рабочие правила и маршрутизация к нужным справочникам.
- `references/00-index.md` - `references/11-merge-cfg.md` - модульная документация.
- `references/archive/verified-documentation-full.md` - полный архив документации
  с обезличенными примерами; не является проверкой новой базы.
- `scripts/search-docs.ps1` - точный локальный поиск.
- `scripts/validate-skill.ps1` - структура, frontmatter, ссылки, UTF-8, критические
  правила и контрольные суммы manifest.
- `tests/test-cases.md` - сценарии проверки.
- `manifest.json` - состав и контрольные суммы этой обезличенной упаковки.
- `install.ps1` - сохранённый вспомогательный ресурс установки отдельного навыка.

## Подключение в проекте

Развёртывание всего проекта выполняет агент по текстовой инструкции распакованного шаблона.
[Рабочие правила ядра](../../AGENTS.md) сохраняются после установки и определяют
дальнейшую разработку и очистку временных материалов.
Для проекта сохраняется весь каталог навыка с вложенными ресурсами. Выбранные область
установки, способ регистрации и версия платформы выясняются в опросе. Агент может
читать `SKILL.md` и его ресурсы непосредственно по пути в текущем проекте.
Для другой платформы необходима отдельная проверка применимости.

Не запускайте `install.ps1` автоматически при настройке проекта. Для выбранной
регистрации агент использует доступные инструменты и предварительно сравнивает
существующие файлы. Наличие копии навыка не подтверждает его регистрацию в клиенте.

## Локальная проверка

```powershell
.\scripts\validate-skill.ps1
.\scripts\search-docs.ps1 -Query 'DumpConfigToFiles'
```

Командные примеры содержат обозначения `<PLATFORM_EXECUTABLE>`, `<SERVER>`, `<INFOBASE>`,
`<PROJECT_ROOT>` и другие заполнители. Значения получают только из текущего профиля.
Они не являются готовыми командами для запуска. По умолчанию проект использует логин
и пароль информационной базы; Windows-аутентификация выбирается отдельно только для неё.
Хранилища конфигурации имеют собственные адрес, пользователя и источник пароля.

Статическая проверка упаковки не подтверждает выполнение операций 1С в новом окружении.
Границы текущей проверки описаны в `BUILD-REPORT.md`.
