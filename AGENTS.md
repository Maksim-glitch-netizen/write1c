# Развёртывание проекта 1С из шаблона

Этот файл задаёт входные правила распакованного шаблона. При установке в новую папку
не копируй его в целевой проект и не создавай там другой корневой AGENTS.md.
Рабочие правила целевого проекта находятся в `1c_core/AGENTS.md`.
Все пути профиля разрешаются от выбранного целевого корня. Не подставляй базу,
пути, авторизацию и расширения другого проекта.

## Первое действие в каждом чате

1. Прочитай [README запуска](README.md),
   [текстовую инструкцию настройки](1c_core/docs/развертывание/ИНСТРУКЦИЯ.md), состояние
   и реальный профиль, если он существует. Отличай распакованный шаблон от готового проекта.
2. На команду «установить» из незаполненного шаблона сначала предложи одним вопросом
   целевую папку: конкретный новый свободный путь рядом с шаблоном (рекомендуется)
   либо возможность указать другой путь. Если выбран только вариант без пути,
   следующим отдельным вопросом запроси путь. Известный путь повторно не спрашивай.
   Проверь выбранный каталог по инструкции, подготовь целевой комплект и далее
   веди опрос, профиль, состояние и lock только в целевом проекте.
3. Для разработки в подготовленном проекте полностью прочитай
   [рабочий AGENTS ядра](1c_core/AGENTS.md). Все этапы разработки и ограничения находятся там.
4. Если пользователь исправляет сам эталон, работай с файлами как с обезличенным шаблоном;
   не начинай опрос о реальной базе и не заполняй профиль ради проверки текста.
5. Запрос объяснения или анализа сам по себе не запускает развёртывание и операции базы.

## Опрос и источник исходников

Задавай строго один вопрос за раз и дождись ответа перед следующим. Один вопрос
запрашивает одно значение или одно решение; не объединяй в нём несколько полей.
Если ответ можно выбрать из понятных вариантов, предложи варианты и возможность своего ответа.
После ответа сохрани полученное значение; уже известное повторно не спрашивай.

Назначение базы фиксировано: РАЗРАБОТКА (DEV), `database.environment=development`.
Вопрос о назначении базы не задаётся. По умолчанию используется логин и пароль базы;
при выборе Windows-аутентификации запуск выполняется под текущей учётной записью
процесса агента, без отдельного вопроса о Windows-аккаунте.

Для пароля базы или любого хранилища обязательно предложи один вопрос с вариантами:
«Каким способом передать пароль?» — «Локальный файл», «Переменная окружения»,
«Доступное хранилище секретов». Если пользователь спрашивает, как передать пароль,
покажи этот выбор с коротким пояснением каждого способа. После выбора отдельно запроси
путь к файлу, имя переменной или ссылку на запись. Не запрашивай значение пароля в чате.
В профиле сохраняй только `password_ref`; известный способ или реквизит повторно не спрашивай.

Источник актуальных исходников — рабочая конфигурация Конфигуратора либо хранилище
конфигурации. Сначала отдельно выясни наличие хранилища. Предлагай его как источник
только после подтверждения наличия; при отсутствии используй рабочую конфигурацию.
При наличии предложи выбор источника отдельным вопросом. Для расширения учитывается
его собственное хранилище. Подробный порядок выгрузки находится в AGENTS ядра.

Для неизвестного списка расширений предложи один вопрос: «Как получить список расширений?»
с вариантами «Определить автоматически», «Указать вручную», «Расширений нет».
Автоматическое определение предлагай при доступном подключении и разрешённом безопасном
чтении текущей базы. Полученные точные имена сохраняй и повторно не спрашивай.
Выбранный способ сохраняй в `extensions_discovery.method`; остальные свойства расширений
уточняй отдельно, по одному вопросу.

## Структура

В распакованном шаблоне находятся README.md, этот входной AGENTS.md, .gitignore,
ядро `1c_core` и рабочая папка `1c_works_files`.
В целевой проект переноси README.md, .gitignore, ядро и рабочую папку,
исключая корневой AGENTS.md и служебные навыки `1c-core-skills` и `1c-project-setup`.
Не удаляй автоматически корневой AGENTS из ранее существовавшего проекта.
Имена этих двух папок фиксированы всегда: не спрашивай их выбор и не предлагай другой путь.
Используй ядро распакованного шаблона и адаптируй его копию в целевом проекте;
вопрос об источнике ядра не задаётся. Распакованный шаблон сохраняй незаполненным.
Полный исходный набор рабочих skills находится внутри ядра; docs обязательна.
Настройка выполняется напрямую по текстовой инструкции в docs; служебный skill настройки
не включается в состав проекта и не устанавливается при развёртывании.
Опрос, профиль, состояние, блокировка и результаты настройки размещаются только
в `1c_core/docs/развертывание/` целевого проекта. Рабочие правила - только в `1c_core/AGENTS.md`;
отдельного `ПРАВИЛА-ПРОЕКТА.md`, папки шаблонов и дополнительной папки skills в корне нет.
`1c_core/docs/verified-1c-commands/` остаётся пустой при настройке и до разработки.
После завершения агент обязательно очищает `1c_core/docs/развертывание/` в целевом
проекте по инструкции и рабочим правилам ядра: оставляет профиль и состояние,
сохраняет исходники в рабочей папке и удаляет только подтверждённые временные материалы
этой установки. Сам распакованный шаблон не очищает. Завершение развёртывания и его
очистки фиксируется в `deployment` состояния отдельно от технической готовности.
По завершении сообщи целевой путь: пользователь создаёт новый проект агента с этой
папкой и её `1c_core`, как описано в README.

## Границы

Настройку выполняет агент по текстовой инструкции. Не создавай универсальный установщик
и не запускай встроенный install.ps1 для развёртывания всего проекта.
Согласуй работу нескольких чатов по lock; не меняй общие файлы другого активного владельца.
Не очищай компоненты, выгрузки и чужие задачи. Настройка не разрешает менять бизнес-данные.
Секреты не записываются в профиль, тексты, журналы, Git и память.
Учитывай выбранную область памяти либо её прямой запрет **до любых вызовов памяти**.
Реальные адреса, пользователи и локальные пути допустимы только в настроенной копии;
чистый эталон содержит относительные пути, неизвестные поля и универсальные обозначения.
